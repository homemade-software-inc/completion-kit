# Accessibility audit — engine authenticated pages (2026-05-22)

A WCAG 2.1 AA pass across the engine's authenticated views (prompts, datasets,
metrics, metric groups, runs, responses, suggestions, provider credentials,
tags, onboarding, API reference). The audit followed up #47 (the `--ck-dim`
contrast fix, already landed) and was tracked under #48.

This is a sampling-and-pattern audit, not a per-element checklist. Where one
view exposes a pattern (e.g. forms or index tables), the finding applies to
the rest of the views that share the pattern, and the fix is filed as a
sweep-style sub-issue.

## Positives — what is already in good shape

- The engine layout has the right top-level landmarks: `<header class="ck-topbar">`
  (banner), `<nav class="ck-nav">` (now `aria-label="Primary"`), and
  `<main class="ck-main">` (now `id="ck-main-content"` for the skip link).
- Flash messages have `role="status"` for notices and `role="alert"` for
  alerts, so success and error banners are announced.
- The hamburger menu and the cog menu are native `<details>`/`<summary>` (keyboard
  expandable, no JS needed) with explicit `aria-label`s and `aria-hidden` icons.
- Form labels use `form.label` everywhere, which produces a real
  `<label for="…">` matched to the input.
- The logo `image_tag` has an `alt`. Decorative inline SVG icons carry
  `aria-hidden="true"`.
- `--ck-dim` raised to `#7a8aa3` for WCAG AA contrast (#47, shipped in 0.5.32+).
  `--ck-muted` already passes.

## Fixed in this pass

- **Skip-to-content link.** Added an off-screen-until-focused
  `.ck-skip-link` as the first focusable element in `<body>`, targeting
  `<main id="ck-main-content" tabindex="-1">`. Lets keyboard and screen-reader
  users bypass the topbar. (WCAG 2.4.1 Bypass Blocks.)
- **`<nav aria-label="Primary">`** on the topbar nav, so multiple navs (the
  topbar and the cog menu inside it) are distinguishable.
- **Settings dropdown panel: removed `role="menu"`.** The panel is a list of
  links, not a true ARIA menu widget — the children were `<a>` elements
  rather than `role="menuitem"`, which made the ARIA pattern incomplete.
  Removing the role keeps the panel a plain, accessible group of links.
- **`#refresh-status` is a live region.** The status paragraph used by the
  "refresh provider models" flow now has `role="status" aria-live="polite"`,
  so updates like "Refreshing models… 3/12" and "Models updated." are
  announced.

## Deferred to sub-issues

Each item below is a sweep across multiple views and warrants its own ticket.

1. **Index-table rows are not keyboard-accessible.** Every index page
   (prompts, runs, datasets, metrics, metric groups, tags, provider
   credentials) renders rows that navigate via `onclick="window.location=…"`
   on the `<tr>`. The primary record name in the first cell is a `<strong>`,
   not a link. A keyboard user has no way to activate the row. Fix: make the
   primary record name a real `<a>` (the row-onclick can stay as a
   mouse convenience). Also add `<th scope="col">` to the header cells.
2. **Form error ARIA.** The error block at the top of `*/form` partials
   (when `model.errors.any?`) is a styled `<div class="ck-flash--alert">`
   without `role="alert"`, so it is not announced when validation fails.
   Per-field errors are not associated with the invalid input via
   `aria-invalid` / `aria-describedby`. Fix: add `role="alert"` to the
   error summary; add `aria-invalid="true"` and `aria-describedby` linking
   each invalid input to its message.
3. **Deeper widget pass.** The run status panel, the response card, the
   suggestion view, and the tags picker are richer interactive surfaces that
   need a fuller audit (heading hierarchy, focus order, dynamic-content
   announcements). Out of scope for this pattern-level pass.

## Methodology

- Engine layout reviewed end-to-end.
- One representative form (`prompts/_form.html.erb`) and one representative
  index table (`prompts/index.html.erb`) sampled; findings generalised to the
  pattern.
- `Rails.logger`, error-tracker context, and provider data flow are out of
  scope for #48 — they are covered in `docs/privacy/data-flow.md` (#45).

## Scope note for hosts

Hosts that mount the engine in a custom layout (rather than using the engine
layout) inherit responsibility for the layout-level landmarks and the skip
link. The engine's `<main>`/`<nav>`/`<header>` structure documented here is
only present when the engine layout is in use; see
`README.md#host-app-layout-integration`.
